# AstraPlusCar HarmonyOS 手机控制端

本应用的目标版本与最低兼容版本均为 HarmonyOS API 23。手机、小车、电脑接入同一个 WLAN 后，在连接页填写小车 HTTP 地址；2026-09-30 实车联调地址和当前默认值为 `http://192.168.8.204:8080`。地址变化时以小车实际 IP 为准。接口及部署方式见 [Phone API](../AstraPlusCar-device/docs/PHONE_API.md)。

## 界面与控制

连接状态采用居中小车与左右分支布局：左侧为视频、雷达，右侧为语音、模型，四个模块分别通过连接线接到小车，表示它们依赖车辆连接。视频与雷达只有在小车连接且对应模块就绪时显示在线；语音与模型暂固定显示离线。主页和连接页复用同一组件，状态区域保持紧凑。本次布局已通过 HAP 构建，并在鸿蒙手机上复核主页、连接页的四条连线与文字显示；验证时小车未连接，未发送运动指令。

视频默认使用有界短段 MJPEG，目标 30 FPS：请求 `/api/v1/camera/stream.mjpg?fps=30&frames=12`，每段正常传完 12 帧后关闭，每 300 ms 提前开启下一段，最多三个请求在途。单段最长保留 900 ms，忽略开始超过 750 ms 后到达的数据，并以各段的 `X-Frame-Sequence` 丢弃重复/倒退源帧。单个连接重传时，后续短段可独立送帧；正常播放保留连续收包，避免高频单图 HTTP 的开销。车端仍支持持续 MJPEG 与单帧接口。相机按 720p / 30 FPS 采集，驾驶预览为 640×360，截图保持 720p；界面显示实际解码 FPS，重复源帧不会刷新看门狗。连接预览时保持窗口亮屏，连接前固定局域网路由并禁用 HTTP 代理。超过 2 秒无新画面会断开控制并发停车；已有画面的连接在前台等待 0.5 秒自动重连一次，连接或恢复失败则提示手动连接。收到新画面前禁止运动和调速，不恢复旧会话、按键或运动。主动断开、取消连接或退后台会取消重连，车端 600 ms 看门狗继续生效。状态轮询不重叠，旧连接的迟到响应不能覆盖新连接；车端重启后重新建连。

竖屏主页依次显示连接状态、16:9 视频、视频下方独立雷达条、控制盘和底部“停车 · 急停”按钮。雷达按“左、前、右”排列，距离明确显示为米（例如 API 的 100 mm 显示为 0.10 m）；提示阈值暂定为红色 ≤0.20 m、黄色 0.20–0.50 m、绿色 >0.50 m。没有回波显示灰色“未测得”，雷达不可用或数据过期显示“未就绪”；不将无读数解释为安全距离，也不对正数读数设置 100 mm 的下限。距离来自雷达安装零位下的 270°、0°、90° 方向各 ±30° 范围内最近回波，按雷达中心计算，需要确保零位朝向车头。近距离无回波可能涉及雷达盲区，不能仅靠 App 换算解决，需结合实车距离与原始读数核对。

连接页显式顶部对齐，重新打开时回到顶部。最上方为带“车端地址”标签和 Wi-Fi / IP / 端口说明的连接框，下方依次为连接状态、视频与雷达。页面保留前、左、右三向原始毫米读数、最近扫描的数据龄、颜色阈值与测量说明，便于现场校验。手机每 250 ms 轮询状态，同一连接内不重叠请求；当前车端约每秒发布一个最近回波窗口，App 更快轮询减少取到新窗口的等待，不能提高硬件或车端的发布频率。数据龄直接使用车端的单调时钟年龄，避免车端日历时间不准确影响显示。

控制盘中间为“截图”，触摸视频也可截图；屏幕最底部保留独立的“停车 · 急停”。四个主要方向是前进、左转、后退、右转，四角是左右旋转与左右平移。右侧按钮文字位于对应触摸区域内。按住运动区时仅允许一个动作生效，第二个手指不能同时触发另一方向；滑到新方向时先停车再切换，松手或触摸取消即停车。速度滑块在运动按住期间同样可用：拖动时约每 120 ms 提交最新速度，沿用当前运动会话与续期 ID，不必松开方向。松手、急停或换方向后的迟到调速响应不会更新新动作。断联、App 退后台和画面方向切换时释放当前动作；车端还有 600 ms 控制续期看门狗。

横屏隐藏 HdsNavigation 标题栏（标题位置留空），内容区因此等于整个窗口，不再有标题栏高度在底部留下的空带；“连接 / 图库”改为画面右上角的两个圆形叠加按钮，横屏仍可打开连接页和图库，图库页保留自己的标题栏与返回按钮。16:9 视频保持原始比例居中显示（`ImageFit.Contain`）：屏幕比 16:9 更宽时左右黑边对称，更高时上下黑边对称，不再出现只有一侧的黑边或裁切画面。摇杆、速度滑块与雷达色带叠在画面上，用单条 12 vp 宽的椭圆色带显示前、右、左三向迫近提示，不绘制后方，也不按危险程度增加条数。只有有效距离 ≤0.50 m 的方向才显示色带和距离，较远、无回波或雷达不可用时隐藏。黄色与红色区分警戒程度；不透明度随距离缩短从 20% 连续提高，最高 50%，色带两端渐变至透明。颜色与深浅变化使用 320 ms 平滑动画，出现和消退使用 280 ms 淡入淡出。环内部透明，整层不拦截控制触摸。竖屏与连接页仍保留三向距离和雷达可用状态。横屏左侧摇杆控制前进、后退、左右转弯，中央是停车；右侧摇杆左/右为左旋转/右旋转，上/下为左平移/右平移，中央是截图；速度滑块位于画面左上角，容器高 32 vp，底色不透明度约 33%，减少对中央视野的遮挡。两套摇杆同样互斥。摇杆文字位置与宽度在构建时按当前摇杆直径计算（只把固定比例传给 `@Builder`，直径在构建器内部读取），随尺寸变化刷新，不再停留在首次布局的旧尺寸上。需要人工停车时可使用左侧中央按钮。连接页在横屏可滚动。

截图先保存在车端，再下载到应用私有图库，重启后仍可查看。用户主动选择“下载”并完成系统授权后，图片才进入系统相册。车端没有日志流接口，因此应用不提供控制台页面。

## 构建与联调

在本仓库执行：

```bash
/Users/raychen/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw \
  assembleHap --mode module -p product=default -p module=entry@default \
  -p buildMode=debug --no-daemon
```

调试包位于 `entry/build/default/outputs/default/entry-default-signed.hap`。2026-09-30 已在真机安装构建包，并在同 WLAN 下连到真实小车，确认视频、三向雷达、截图与手机私有图库；API 侧确认了状态、MJPEG、截图下载、速度、全部方向命令、续期、停车、旧会话拒绝和 600 ms 失联自动停车。车轮悬空时仅做短时运动命令；实际轮向、落地行驶和 App 后台停车还需现场观察。此后已将统一主程序部署到原车载目录，并安装和启动正式 `astra-phone.service`，通过 `main.py --mode phone` 运行，未设置开机自启。详细状态和服务部署说明见设备端 README 与 Phone API。

当前修改已通过 HAP 构建和 Node 离线回归检查（MJPEG 任意分包、最新帧丢弃策略、长度上限，以及按住调速、动作开始时调速、会话创建取消、停车后迟到响应，以及视频请求前绑定局域网）。可在仓库执行 `node tools/check-phone-control.cjs`；脚本默认使用本机 HarmonyOS SDK 的 TypeScript 编译器，也可用 `ARKTS_TYPESCRIPT` 指定其路径。手机无线调试地址变化后需重新连接；当前新包已在在线手机更新安装，视频与雷达预览已成功连接，手机解码日志约 29–31 FPS；电脑同 WLAN 连续接收 300 帧测得 29.91 FPS、序号零跳帧。帧率会随相机、无线网络与手机负载波动，这次未进行新的落地行驶测试。

`node tools/check-camera-stream.cjs` 验证短段并发上限、单个停顿不阻塞新段、按源序号隔离旧帧、正常段结束、停止取消、重复源帧不刷新看门狗，以及两种传输模式保留 2 秒保护。短段要求每帧返回 `X-Frame-Sequence`，缺失时明确停止并提示更新车端。

实现依据：[华为流式 HTTP 示例](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/data-augmentation-rag-development)、[华为图片解码与资源释放文档](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V14/image-decoding-V14)，并通过本机 API 23 SDK 与 ArkTS 编译器验证。
